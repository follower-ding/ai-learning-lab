# 第 03 课：切块与向量

长规章不能整篇塞进一次提示，也不能整篇压成一个向量。这一课先切开，再把文本变成可以比较方向的数字。

## 学习目标

- 中文按字符窗口切，尽量在句号处断开，相邻块保留重叠。
- 说清楚本课的向量是字符二元组上的 TF-IDF，不是神经网络嵌入。
- 查询和文档共用同一次 `fit` 得到的 idf。

## 概念笔记

`chunk_text` 先按空行分段落。段落短于窗口就整段留下；更长的段落再滑动。窗口后半段如果有 `。！？；`，就在那里切开。下一块从切口往回退 `overlap` 个字符，避免一句话正好卡在边界上。

`overlap` 必须小于 `size`。否则窗口不前进，函数会直接拒绝，而不是转圈。

向量这一侧，`TfidfEmbedder` 取相邻两个字符当「词」。词频取对数，再乘 idf：很多规章里都出现的「时间」权重低，区分度高的「入住」「早餐」权重高。余弦看的是方向。没在文档里出现过的二元组会被丢掉；查询如果全是新词，向量就是 0，余弦也是 0。

这套向量只奖励字面重叠。「我什么时候能进房间」和入住规章讲的是邻近的事，分数却会掉一截，因为共用的二元组不多。「今晚有乐队演出吗」应当是 0。神经网络嵌入要换的时候，实现同一个 `embed` 即可。`OpenAICompatibleEmbedder` 就是这个接口的 HTTP 版本，维度由模型决定，旧向量不能混用。

先 `fit` 文档，再 `embed` 查询。给查询单独 `fit` 一套新的 idf，文档向量和查询向量就不在同一个空间里，余弦没有意义。

切块也影响字面向量：一块里主题越多，关键词的权重越被冲淡。神经网络嵌入则是一块里混进多个主题。两种向量都希望一块主要说一件事。短问答在下一课整段入库；这一课的长规章才需要切。

## 跑起来

```bash
python lessons/03-embedding-chunking/exercise.py
```

在仓库自带的规章上，三行余弦大约是 0.40、0.23、0.00。你改了资料之后数字会变，顺序应当还在：字面重叠最高，完全无关为 0。0.23 那句在第 05 课里会擦着 0.2 的阈值，读下一课时记得这件事。

建议改一行：把 `overlap` 改成 `80`（和 `size` 一样）。练习应当直接报错，而不是卡住。

## 常见坑

- 用空格给中文分词。规章会几乎切不开。
- 把 TF-IDF 讲成「语义嵌入」。它不会因为两句话意思接近就给出高分。
- 文档和查询各 fit 一次。
- 换了嵌入模型却留下旧向量。维度不同，第 04 课的库会拒绝写入。
