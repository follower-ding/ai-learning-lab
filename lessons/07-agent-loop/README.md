# 第 07 课：有上限的循环

第 06 课是一轮。这一课把「模型 → 解析 → 执行或结束 → 写回消息」重复几次，并且规定它一定会停。

## 学习目标

- 用 `max_steps` 限制轮数，默认 4。
- 相同工具名和相同参数出现第二次就停。
- 停下来时说明原因，不用猜测把价格补圆。

## 概念笔记

`run_agent` 每一轮调用一次 `complete`，然后只接受三种情况：

- `final`：把 `answer` 交给客人，停止原因是 `final`。
- `tool_call`，而且名字在允许列表里：执行函数，把结果写成一条 `role="tool"` 的消息，再进入下一轮。参数不合法时，写回的是「工具参数错误：……」，循环继续，让模型可以改参数。
- JSON 解析失败：消耗一步，把「只输出一个 JSON 对象」发回去，然后继续，直到步数用尽。
- 名字不在列表里：不执行，停止原因是 `unknown_tool`。签名重复：不执行第二次，停止原因是 `repeated_tool`。步数用尽：停止原因是 `max_steps`。

签名是工具名加上排序后的参数 JSON。`{"hours": 2}` 和再次出现的同样调用算重复。每步换成 1 小时、2 小时、3 小时则不算重复，这时靠 `max_steps` 停。两个限制挡的不是同一种循环。

达到上限时，给客人的话是「达到步数上限，已停止。」即便前面的工具已经算出 30 元、60 元，也不把最后一次价格当成正式回答。那些价格留在步骤记录里，供你排错，不自动升级成答案。

真实 HTTP 客户端发送时，会把 `tool` 消息改写成 user 文本，内容仍是函数返回值。Mock 则直接读 `role="tool"`。启发式 Mock 一看到工具结果就输出 `final`，所以正常计价是两步。要观察「一直换参数」这种多步行为，用 `script=` 按顺序喂回复。脚本用完会报错，不会偷偷改回启发式。

## 跑起来

```bash
python lessons/07-agent-loop/exercise.py
```

正常那次应当是两步：先 `quote_late_checkout`，再 `final`，回答里有「合计 60 元」。后面那段脚本每步一个小时数，`max_steps=3`，停止原因是 `max_steps`，正式回答里不出现价格。

建议改一行：把正常那次的 `max_steps` 改成 `1`。循环会停在工具调用之后，来不及 `final`，正式回答是步数上限那一句。

## 常见坑

- 不设步数上限。模型可以一直换参数。
- 重复调用时继续执行。相同问题会被计费、被重复写入。
- 上限到达后，把某一次工具结果挑出来当最终答案。客人没有得到「这是不完整的一轮」这个信息。
- 解析失败就让异常冒出请求。应当消耗一步，并把「只输出 JSON」发回去；步数仍然要算。

## 口头自查

1. 步数上限，和「相同工具、相同参数只许一次」，各挡住哪一种停不下来的情况？
2. 达到上限时，给客人的句子和正常计价结果有什么不同？工具已经执行过，为什么不把最后一次价格当成答案？
3. 工具结果用什么 `role` 写回？真实客户端为什么又把它改成 user 消息？
