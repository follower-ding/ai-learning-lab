# 第 08 课：小评测

前面每一课都能跑出一段看起来合理的话。这一课用 9 条例固定行为：该引用的要引用对，该拒绝的要拒绝，该走工具的要走那只工具，不该猜的价格不能出现。

## 学习目标

- 区分「评应用行为」和「给模型打榜」。
- 同一句话在检索路径和工具路径上可以有不同期望。
- 用例失败时去看 `reason`，而不是改期望迁就输出。

## 概念笔记

用例在 `src/ailab/data/eval_cases.json`。每条写明 `kind` 是 `rag` 还是 `agent`，以及 `expect`：

- `cite`：不拒绝，且引用里有指定的 `source_id`。
- `refuse`：回答就是那句固定拒绝，没有引用。
- `tool`：停止原因是 `final`，步骤里出现了指定工具。
- `no_tool`：停止原因是 `final`，一步工具都没有。

`forbid` 和 `require` 再查回答里的片段。延迟退房的单价是 30 元一小时，所以 3 小时必须出现 `90`。检索路径禁止出现 `30`、`60`、`90`，因为规章正文里没有这些数字。

「延迟退房怎么收费？」被用了两次，期望不同：

- 检索：引用 `faq-checkout`，复述「先问前台是否有空房」，不出现单价。
- 工具：没有小时数，就反问，不调用计价工具。

再给一条「延迟退房 3 小时要多少钱？」，才要求 `quote_late_checkout` 和 `90`。三条合在一起，才能说明价格来自工具，而不是模型或规章里编出来的。

期望不要写进系统提示。提示里如果已经有标准答案，分数只说明模型会照抄，不能说明检索和引用检查在工作。用例就这几条，所以每条都针对一种失败：引用错文档、不该答时答了、缺参数时猜价格、该算时没算。

## 常见坑

- 只放能够回答的问题。拒绝和「不许猜价格」这两种故障不会出现。
- 一条用例不写路径。同一句话检索和工具都算「答了」，你不知道是哪段代码的功劳。
- 失败了就放宽 `expect` 或删掉 `forbid`。评测就不再看守原来的坑。
- 把这 9 条的通过率说成模型能力分数。这里用的是 Mock 和字面向量，测的是你写的门槛、引用检查和工具循环。
