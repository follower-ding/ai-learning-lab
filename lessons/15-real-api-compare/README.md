# 第 15 课：换成真实接口的对照

第 08 课那 9 条，到这里一直是 Mock 和字面向量在答。这一课只做一次对照：离线结果先留在屏幕上。仓库根目录的 `.env` 里有密钥时，再把 `complete` 换成真实 HTTP 接口，看引用、拒绝和工具是否还成立。

没有密钥也能做完。练习会写明跳过了真实调用，退出码为 0。不要把离线结果抄成「已经调用了真实接口」。

## 学习目标

- 用第 08 课的同一套用例，并排看离线 Mock 和一次真实接口。
- 看见真实客户端上的超时和 `max_tokens`：一个限制等待，一个限制这一次生成的长度。
- 分清三件事：引用是否还落在检索到的文档上，拒绝是否还是那道门槛，工具是否还只走允许列表里的那两只。

## 概念笔记

对照的是第 08 课，不是另写一套题。`run_eval()` 不传客户端时，仍是 Mock，和第 08 课相同。这一课只在手动运行、并且读到密钥时，才把同一个 `client` 传进去。检索和工具两路的 `complete` 都换成这一个客户端。

检索不换。问题仍用第 03 课的字面向量去第 04 课的库里找，门槛仍是 `DEFAULT_MIN_SCORE`（0.2）。所以游泳池和机场接送这两条，最高分不到 0.2，模型不会被调用。离线如此，接上真实客户端也如此。它们若仍然拒绝，说明门槛还在，不是模型学会了说「不知道」。

过了门槛的引用，和工具那三条，才会把消息发给 `/chat/completions`。真实模型可能写出 `[faq-pool]` 这种没检索到的 id，引用检查会整段作废，第 08 课的 `cite` 就不再通过。工具仍要求 JSON：`tool_call` 或 `final`。模型若写成自然语言，循环会停在步数上限，工具那一组就有变化。允许列表仍然只有 `lookup_policy` 和 `quote_late_checkout`。

`OpenAICompatibleClient` 构造时收下 `timeout` 和 `max_tokens`。超时交给 HTTP 客户端，到点就不再等。`max_tokens` 写进请求体。默认 30 秒和 400。`.env` 里可以用 `OPENAI_TIMEOUT` 和 `OPENAI_MAX_TOKENS` 改。没写就用默认。

密钥只从仓库根目录的 `.env` 读，变量名是 `OPENAI_API_KEY`。没有这把密钥时，`live_client_from_env` 返回 None，练习不构造 HTTP 客户端。`client_from_env` 在没有密钥时会退回 Mock。这一课不用那个退回：退回的 Mock 仍是离线结果，不能记成真实对照。

这一课不读 `OPENAI_EMBEDDING_MODEL`，也不重建向量库。换嵌入模型后维度会变，第 04 课的库要整库重算，0.2 那道缝也要重新看分数。那是另外一件事。

第 01 课到第 14 课不读这些变量。`python -m pytest` 默认仍用假传输，不跑这一次真实对照。已有的那条 `integration` 测试，没设置密钥时仍跳过。

## 跑起来

没有密钥时：

```bash
python lessons/15-real-api-compare/exercise.py
```

应当先看到离线 Mock 的 `合计 9/9`，以及「离线：引用成立，拒绝成立，工具成立」。接着是「跳过真实接口」，并写明超时和 `max_tokens`。退出码为 0。屏幕上没有真实接口的结果。

要做那一次对照时，在仓库根目录把示例文件复制成 `.env`，只在本机填上密钥。不要把填好的 `.env` 提交进仓库。

```bash
cp .env.example .env
```

Windows 可以把 `.env.example` 复制成同一目录下的 `.env`。用编辑器填上 `OPENAI_API_KEY`，需要的话再改 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_TIMEOUT`、`OPENAI_MAX_TOKENS`。然后仍运行上面的练习。

有密钥时，屏幕上先是同一份离线报告，然后是真实接口这一侧的报告，最后一行写明引用、拒绝、工具是「仍成立」还是「有变化」。这次对照不要求真实模型也得 9/9。退出码仍是 0。接口没有完成时，只打印已经脱敏的失败原因，不编一份结果。

第 01 课到第 14 课，以及默认的 `python -m pytest`，都不需要这把密钥。

建议改一处：把跳过时的那句「这次没有调用网络，也没有真实接口的结果。」改成「真实接口：引用仍成立，拒绝仍成立，工具仍成立。」没有密钥时练习仍会以退出码 0 结束，但这句话是假的。看完改回去。不要为了变绿去改测试里的「没有真实接口的结果」，也不要让默认 `pytest` 去联网。

## 常见坑

- 没有密钥时，把离线的 9/9 写成「真实接口也通过了」。Mock 没有离开这台机器。
- 用 `client_from_env` 的 Mock 退回冒充真实对照。没有密钥时它就是第 08 课的脚本。
- 把这一次真实调用写进默认 `pytest`。没有密钥的人一跑测试就会去联网，或者被迫准备密钥。
- 为了让真实模型更容易答对，去改 `RagPipeline.answer`，或改第 06 课到第 14 课的默认路径。对照要看的就是现有路径还成不成立。
- 换嵌入模型，却不重算第 04 课的库。维度对不上，0.2 也不再是原来那道缝。这一课不换嵌入。
- 把密钥、`.env` 的内容、`Authorization` 头或 `sk-...` 写进仓库、测试、练习输出或提交说明。报错文本要走已有的 `redact`。
- 不设超时和 `max_tokens`。一次调用可能一直挂着，或者写出很长的正文。

## 口头自查

1. 没有密钥时，屏幕上的「离线：引用成立，拒绝成立，工具成立」为什么不能写成「真实接口也成立」？
2. 游泳池那一条接上真实客户端之后，为什么往往仍然拒绝，而且这一条多半没有发出对话请求？
3. 超时和 `max_tokens` 各限制哪一件事？为什么这次对照不该变成默认 `pytest` 的通过条件？

口头回答即可。说不顺的那一题，把练习里「离线」那一行和「跳过真实接口」那一行并排再讲一遍。
